Set Up A Minimal Project

This is the smallest working shape described by the added walkthrough notes: an HTML host page, one module script, and a local server that serves the directory. The engine does not require a framework; it just needs a page that loads your module.

Step By Step

  1. Create a project directory that can serve static files.
  2. Add an HTML file that loads your simulation script as a module.
  3. Add a JavaScript or TypeScript entry file that imports Main and calls Main.run(...).
  4. Serve the directory over HTTP instead of opening the file directly from disk.
  5. Use fps = 0 when you want a single frame for debugging, or a positive value for a continuous loop.

Minimal Host Page

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Engine Sandbox</title>
</head>
<body></body>
<script type="module" src="./test.js"></script>
</html>

Minimal Entry File

import { Main } from '../dist/main.js';

Main.run(60);

Serve It Locally

  • From the project directory, run python3 -m http.server 8080 or any equivalent static file server.
  • Open the served page in a browser instead of relying on a file URL.
  • If the engine is not running, the background color acts as a reminder that the page is loaded but the simulation loop is idle.

Create Your First SimObject

This is the direct bridge between the new walkthrough notes and the engine reference: build one polygon, wrap it in one Part, attach that part to a SimObject, then finalize and register it.

Concepts In Play

  • Polygon defines the visible geometry.
  • Part is the attachable unit that holds geometry and child parts.
  • SimObject is the world object that owns the part tree.
  • Sim stores finalized objects in the simulation.

Step By Step

  1. Create a polygon and choose a built-in or custom Mien.
  2. Create a Part around that polygon.
  3. Create a uniquely named SimObject and choose its movement mode.
  4. Attach the part to the object with addTo(simObject, { x: 0, y: 0 }).
  5. Call finalize() before adding the object to Sim.
  6. Register it with Sim.add(...) and then start Main.run(...).
import { Main } from '../dist/main.js';
import { Sim } from '../dist/sim.js';
import { SimObject, Part } from '../dist/simobject.js';
import { Polygon } from '../dist/polygon.js';
import { Mien } from '../dist/mien.js';

const triangleObject = new SimObject('the-red-triangle', 'always');
const trianglePolygon = Polygon.regular(3, 100, Mien.Red);
const trianglePart = new Part('triangle', trianglePolygon);

trianglePart.addTo(triangleObject, { x: 0, y: 0 });

triangleObject.finalize();
Sim.add(triangleObject, { x: 0, y: 0 }, 0);
Main.run(60);

Why Finalize Matters

  • finalize() is the handoff point where the engine discovers the full part tree and prepares the object for use.
  • The object name must be unique in Sim; part names are mainly for debugging and do not need to be unique.
  • For a root part, the offset is usually { x: 0, y: 0 }; non-zero root offsets are a special case, not the default pattern.

Build A Complex SimObject

Based on test/1_parts.js.

This pattern extends the first-object flow: a SimObject owns a tree of Part instances, and each part holds one or more Polygon shapes. Child parts inherit position and rotation from their parents, so offsets and local rotation become the main composition tools.

Concepts In Play

  • SimObject is the top-level world entity that you add to Sim.
  • Part is the attachable body piece that forms a hierarchy.
  • Polygon describes the geometry for each part.
  • Mien controls appearance and interaction-state colors.

Step By Step

  1. Create a root SimObject and give it a unique name.
  2. Build one or more polygons. In the demo, the base arrow shape is a manually defined point array, which also demonstrates that polygon point order controls how edges are connected.
  3. Create a root Part and attach it directly to the object with addTo(simObject, offset).
  4. Create child parts by scaling or translating the base polygon, then attach them to earlier parts instead of the root.
  5. Assign spin to any part that should animate independently.
  6. Call finalize() on the object once the full part tree is assembled.
  7. Insert the object into the world with Sim.add(...).
import { Main } from '../dist/main.js';
import { Sim } from '../dist/sim.js';
import { SimObject, Part } from '../dist/simobject.js';
import { Polygon } from '../dist/polygon.js';
import { Mien } from '../dist/mien.js';

const ship = new SimObject('demo-ship', 'always');

const hull = new Polygon([
  { x: -50, y: -15 },
  { x: 5, y: -15 },
  { x: 5, y: -50 },
  { x: 50, y: 0 },
  { x: 5, y: 50 },
  { x: 5, y: 15 },
  { x: -50, y: 15 },
], Mien.Green);

const hullPart = new Part('hull', hull);
hullPart.addTo(ship, { x: 0, y: 0 });

const fin = Polygon.translate(Polygon.scale(hull, 0.5), { x: 25, y: 0 });
fin.mien = Mien.Blue;

const finPart = new Part('fin', fin);
finPart.addTo(hullPart, { x: 50, y: 0 }, 0);

hullPart.spin = 0.1;
finPart.spin = -0.3;

ship.finalize();
Sim.add(ship, { x: 0, y: 0 }, 0);
Main.run(60);

What The Demo Adds Beyond The Minimal Version

  • It chains several nested arrow parts so you can see inherited transforms clearly.
  • It uses an invisible Polygon with Mien.Transparent as an anchor point for another orbiting part.
  • It randomizes spin values so multiple objects built from the same pattern do not move identically.
  • When a child part looks attached at the wrong place, check whether the offset includes both the parent reach and the child radius, not just one of them.

Spin Parts And Orbit Shapes

The added walkthrough notes distinguish between three different effects that can look similar at first glance: object rotation, part spin, and an off-center polygon that makes a part appear to orbit its parent.

Concepts In Play

  • SimObject.spin rotates the whole object in world space.
  • Part.spin rotates a child part around its own axis while it stays attached to the parent hierarchy.
  • Polygon.translate(...) can move a shape away from the part origin so the part appears to orbit when it spins.

Step By Step

  1. Attach a child part to a parent with an offset if you want it rigidly mounted away from the parent center.
  2. Set part.spin when you want the child to rotate on its own axis.
  3. Translate the polygon itself before creating the part if you want the visible shape to sweep around the part origin.
  4. Use the two patterns together when you want a nested mechanism that both rotates and appears to orbit.
import { Main } from '../dist/main.js';
import { Sim } from '../dist/sim.js';
import { SimObject, Part } from '../dist/simobject.js';
import { Polygon } from '../dist/polygon.js';
import { Mien } from '../dist/mien.js';

const system = new SimObject('spin-demo', 'always');
const star = new Part('star', Polygon.regular(18, 80, Mien.Yellow));
star.addTo(system, { x: 0, y: 0 });

const translatedPlanetShape = Polygon.translate(
  Polygon.regular(10, 18, Mien.Blue),
  { x: 180, y: 0 }
);

const planet = new Part('planet', translatedPlanetShape);
planet.spin = 0.4;
planet.addTo(star, { x: 0, y: 0 }, 0);

const rigidMoon = new Part('moon', Polygon.regular(6, 10, Mien.Magenta));
rigidMoon.spin = -4;
rigidMoon.addTo(planet, { x: 30, y: 0 }, 0);

system.finalize();
Sim.add(system, { x: 0, y: 0 }, 0);
Main.run(60);

What To Watch For

  • A translated polygon and a zero-offset attachment produce an orbiting visual without moving the part origin itself.
  • An attached child with a non-zero offset follows the parent transform rigidly unless you also give that child its own spin.
  • If a nested mechanism looks wrong, separate the problem into attachment offset, local rotation, and polygon translation instead of adjusting all three at once.

Add Per-Frame Effects

Based on test/2_effects&mouse.js.

Effects in this engine are short-lived renderable objects that you push into Effects. The normal pattern is to generate them inside Main.creatorsFunction, because that callback runs once per frame after the visible simulation objects are rendered.

Concepts In Play

  • Effects manages foreground and background effect arrays.
  • CircleEffect draws a filled expanding disc or arc.
  • RadialEffect draws an expanding ring.
  • LineEffect draws a temporary line between two anchors.
  • ParticleEffect is useful for bursts and plumes.
  • View is how the demo converts mouse coordinates into world space.

Step By Step

  1. Create any simulation objects you want the effects to react to or connect with.
  2. Assign a function to Main.creatorsFunction.
  3. Inside that callback, create effects and add them with Effects.addForeground(...) or Effects.addBackground(...).
  4. For mouse-driven effects, use View.screenToWorld(x, y) so the effect spawns in world coordinates.
  5. For bursts, use ParticleEffect.generateGroup(...) rather than creating every particle manually.
  6. Let the engine remove expired effects automatically; their render() methods return false when finished.
import { Main } from '../dist/main.js';
import { View } from '../dist/view.js';
import { Effects } from '../dist/effects.js';
import { CircleEffect } from '../dist/circle-effect.js';
import { RadialEffect } from '../dist/radial-effect.js';
import { LineEffect } from '../dist/line-effect.js';
import { ParticleEffect } from '../dist/particle-effect.js';

let lastBurst = 0;

Main.creatorsFunction = () => {
  const mouseWorld = View.screenToWorld(View.mouse.x, View.mouse.y);
  Effects.addForeground(
    new RadialEffect(mouseWorld, 5, 20, '#09f', 3, 0.4, 0, 360)
  );

  const now = Date.now();
  if (now > lastBurst + 500) {
    lastBurst = now;
    Effects.addBackground(
      new CircleEffect({ x: -300, y: -300 }, 5, 300, '#f7f', 0.3)
    );
    Effects.addBackground(
      ParticleEffect.generateGroup({ x: 0, y: -100 }, 90, 90, 25, 60, 2, '#f00', 20, 1, 4)
    );
  }
};

Main.run(60);

What The Demo Adds Beyond The Minimal Version

  • It also creates two moving SimObject instances and occasionally draws a LineEffect between them.
  • It bounces those objects manually by clamping world position and flipping velocity when they leave the play area.
  • It uses both foreground and background effect layers so persistent world objects stay readable.

Build Panels, Buttons, and Lists

Based on test/5_gui.js.

The GUI system is panel-based. You create a GUIPanel, then fill it with GUIElement entries by calling addText(...), addButton(...), addList(...), or addGraph(...). Buttons can be attached to GUI elements or directly to world objects.

Concepts In Play

  • GUI maintains the panel registry and handles modal behavior.
  • GUIPanel controls layout, anchoring, and visibility. A panel can be anchored to a screen point, a GUIElement, or a SimObject.
  • GUIElement stores one text/button/list/graph entry.
  • Button handles click logic for both GUI and world objects.
  • Events lets you poll GUI selections from per-frame logic.

Step By Step

  1. Create a panel anchored to screen coordinates or to a world object.
  2. Add text, buttons, and lists to the panel with the relevant helper methods.
  3. For a list widget, pass an array of { textArray, value } items.
  4. Create a second panel anchored to a returned GUIElement when you want a hanging or flyout panel.
  5. For anchored world panels, create the SimObject, finalize it, and add it to Sim first.
  6. Use button callbacks to show or hide subpanels or object-attached panels.
  7. Inside Main.creatorsFunction, query Events if you want frame-based reactions to GUI selections.
import { Main } from '../dist/main.js';
import { GUIPanel } from '../dist/gui.js';
import { Events } from '../dist/events.js';

const panel = new GUIPanel({ x: 0, y: 50 }, 'vertical', { width: 200, height: 200 }, true);
panel.addText(['Inventory'], 'left');
panel.addButton(['Press Button'], 'center', 'button1', false, (data) => {
  console.log('pressed value=' + data.value);
});

panel.addList(
  ['Pick'],
  'center',
  [
    { textArray: ['one'], value: 1 },
    { textArray: ['two', 'with', 'lines'], value: 2 },
    { textArray: ['third one!'], value: 3 },
  ],
  1,
  'horizontal'
);

Main.creatorsFunction = () => {
  const selections = Events.getEvents('listItemSelected');
  for (const event of selections) {
    console.log(event.value);
  }
};

Main.run(60);

Anchored Panel Pattern

const rootPanel = new GUIPanel({ x: 20, y: 40 }, 'vertical', { width: 180, height: 40 });
const menuButton = rootPanel.addButton(['More'], 'center', 'more', false, () => {
  if (detailsPanel.isVisible()) detailsPanel.hide();
  else detailsPanel.show();
});

const detailsPanel = new GUIPanel(menuButton, 'vertical', { width: 150, height: 32 }, false, false);
detailsPanel.addText(['Extra controls'], 'left');

What The Demo Adds Beyond The Minimal Version

  • It creates a subpanel anchored to a text element, then toggles that subpanel with a button.
  • It also creates two world objects and attaches hidden panels to them, then uses Button instances bound directly to those objects.
  • That pattern is useful when you want a clickable world object to reveal contextual information or controls.

Customize Mien

Mien is the engine’s appearance bundle. It carries fill color, border color, text color, font settings, and border width, and it can override those values per mood so the same object renders differently when hovered, pressed, shadowed, or highlighted.

Concepts In Play

  • setColors(bg, border, text, mood?) sets the base colors or one mood-specific override.
  • setFont(name, size, mood?) changes font face and size.
  • setBorderWidth(width, mood?) changes line thickness.
  • Built-in values like Mien.Red, Mien.Blue, and Mien.Transparent are good starting points when you only need a small tweak.

Step By Step

  1. Create a new Mien if you want a reusable custom style, or start from a built-in one when you only need a preset color family.
  2. Set the normal colors first so the object has a stable default appearance.
  3. Add mood-specific overrides for states like hovered, pressed, shadowed, or highlighted.
  4. Pass the Mien into polygons, GUI elements, or panels that should share the look.
import { Mien } from '../dist/mien.js';
import { Polygon } from '../dist/polygon.js';

const warning = new Mien('warning');
warning.setColors('#321000', '#ffb347', '#fff4d6');
warning.setColors('#5a2100', '#ffd27a', '#111111', 'hovered');
warning.setColors('#f7d18b', '#fff4d6', '#111111', 'pressed');
warning.setBorderWidth(2);
warning.setFont('monospace', 16);

const badge = Polygon.regular(6, 24, warning);

Practical Notes

  • Calling setColors(..., 'normal') updates both the explicit normal mood and the base appearance the other moods inherit from.
  • Mien.Transparent is useful for invisible anchors and interaction geometry that should not draw visibly.
  • The same Mien ideas apply to both simulation geometry and GUI widgets, which keeps world objects and panels visually consistent.
